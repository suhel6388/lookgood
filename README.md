# LookGood Live

Real-time webcam effects for any video call. LookGood Live hooks the camera on
the page, runs a WebGL effect pipeline on the frames, and hands the processed
stream back to the site. Skin smoothing, color, light, sharpening, portrait
lighting and background blur are all adjustable live from the popup.

Everything is processed on the device. No video, audio or frame data is ever
uploaded, recorded or sent to a server. There is no account and no payment —
every effect is unlocked.

## How it works

```
page (MAIN world)                      isolated world          extension
┌───────────────────────────┐          ┌──────────────┐        ┌────────────┐
│ content/inject.ts         │          │ content/     │        │ popup      │
│  overrides getUserMedia   │◀─config──│ bridge.ts    │◀──────▶│ React +    │
│  raw camera ─▶ WebGL ─▶   │  status  │ storage +    │        │ Zustand    │
│  canvas.captureStream()   │─────────▶│ badge status │        │ preview    │
└───────────────────────────┘          └──────────────┘        └────────────┘
```

1. `content/bridge.ts` runs in the isolated world at `document_start`. It reads
   `chrome.storage.sync` and posts a config message to the page.
2. `content/inject.ts` runs in the page's MAIN world (declared with
   `"world": "MAIN"`), so it is in place before the site can touch the camera.
   It replaces `navigator.mediaDevices.getUserMedia`.
3. The replacement calls the native function, then feeds the raw stream through
   a hidden `<video>` and a WebGL2 renderer. `canvas.captureStream()` becomes the
   video track returned to the site; audio tracks are passed through untouched.
4. MediaPipe Tasks Vision (selfie segmenter + face landmarker) runs at a lower
   frame rate than the shader loop and produces a person mask and a face mask.
5. Settings changes reach the page over `window.postMessage` and are applied to
   every live pipeline without reloading the call.

The hook fails open: if WebGL or a model cannot start, the raw camera stream is
returned so the call still works.

## Install (unpacked)

```bash
npm install
npm run build
```

Then open `chrome://extensions`, enable Developer mode, choose **Load unpacked**
and select the `dist/` folder. Chrome 116+ is required (`world: "MAIN"` content
scripts and `match_origin_as_fallback`).

## Try it

```bash
npm run test-page   # http://localhost:5174
```

Open the test bench, press **Start camera**, then move sliders in the popup. The
page reports the track label, resolution, frame rate and audio state of the
stream it actually received. The bench also samples the frames, so a black feed
is obvious.

For a real call, open Meet/Zoom/Teams/Discord and join with the camera on. The
toolbar badge shows `ON` while the pipeline is live and `AI` once a MediaPipe
model is loaded.

## Development

```bash
npm run typecheck   # tsc
npm run lint        # eslint
npm test            # vitest (pure settings/preset logic)
npm run build       # popup, content scripts, worker, static assets -> dist/
npm run e2e         # builds nothing: loads dist/ in Brave/Chrome with a fake camera
npm run verify      # typecheck + lint + test + build + e2e
```

`npm run e2e` uses `playwright-core` against an installed Chromium browser
(Brave, Chrome or Edge; override with `BROWSER_PATH`). It loads the unpacked
extension, drives the test page, samples real frames and screenshots the popup
into `.artifacts/`. Set `HEADED=1` to watch it run.

Bundling notes:

- Content scripts and the service worker are built as single IIFE files. ES
  modules are not available to MAIN-world content scripts, and the worker must
  not rely on code splitting.
- MediaPipe's WASM runtime is copied from `node_modules` at build time and kept
  out of git. The two model files live in `assets/models/` and are committed.
- The popup is a normal Vite/React build with Tailwind v4.

```

assets/icons/               generated by scripts/make-icons.mjs

scripts/build.mjs           four Vite builds + static asset assembly
scripts/e2e.mjs             real-browser smoke test
scripts/serve-test.mjs      test bench server
src/background/             stateless service worker (defaults + badge)
src/content/bridge.ts       isolated world: storage <-> page, status -> badge
src/content/inject.ts       MAIN world: getUserMedia override
src/engine/pipeline.ts      hidden video -> WebGL canvas -> captureStream
src/engine/renderer.ts      WebGL2 frame upload and effect passes
src/popup/                  React + Tailwind UI, Zustand store
src/shared/                 settings, message protocol, storage helpers
test/                       local camera test bench
```

## Permissions

- `storage` — save the effect settings.
- Host permissions only for the supported call sites (Meet, Zoom, Teams, Discord,
  Whereby, Jitsi, Webex, Skype, Slack), the WebRTC sample page and localhost.
- `web_accessible_resources` exposes only the MediaPipe WASM runtime and the two
  model files so the page context can fetch them.

No `tabs`, `scripting`, `activeTab` or `<all_urls>` host access is requested.

## Privacy

Camera frames are read into a canvas in the page and rendered locally. Settings
are the only thing stored (`chrome.storage.sync`), and they contain no personal
data. Nothing is transmitted anywhere. The extension does not request network
access for video.

## Known limitations

- Some sites ship a strict Content Security Policy that can block WASM
  compilation in the page context. When that happens the hook fails open and the
  popup reports that AI effects are unavailable on that page.
- The pipeline keeps the page's requested resolution. Sites that call
  `applyConstraints({ deviceId })` are forwarded to the raw track; resolution and
  frame-rate changes are applied to the canvas track.
- A new `getUserMedia` call creates a new pipeline; stopping the returned track
  stops the raw camera and releases the renderer.
- The background service worker is stateless by design, so the popup polls the
  content script for live status instead of caching it.
